# booking-slots

Расчёт свободных слотов онлайн-записи: рабочие графики, отпуска, занятость мастера, буферы уборки и честная очередь листа ожидания.

Модуль извлечён из продакшн-кода SaaS-платформы онлайн-записи [Zapisly](https://t.me/ZapislyBot), которую я написал и поддерживаю, и очищен от инфраструктуры: ни базы данных, ни ORM, ни внешних зависимостей — только stdlib и чистые функции. Это делает ядро логики полностью тестируемым и переносимым.

## Задача

Онлайн-запись выглядит просто ровно до первого реального салона. Дальше выясняется, что:

- мастера работают не «пн–пт с 9 до 18», а по сменам «два через два», причём смена может начинаться в любой день;
- в дне бывает два рабочих окна с перерывом между ними;
- отпуск закрывает день целиком, а обед — только кусок;
- после визита нужно время на уборку, и его нельзя отдать следующему клиенту, но в конце смены уборка спокойно выходит за границу рабочего дня;
- визит из трёх услуг — это один непрерывный блок, а не три отдельных записи;
- нельзя показывать слот «через пять минут», клиенту нужно доехать;
- когда освобождается окно, оно должно достаться тому, кто стоял в листе ожидания, а не тому, кто быстрее обновил страницу.

Каждый из этих пунктов — отдельное правило, и все они пересекаются на одном и том же отрезке времени.

## Установка

Зависимостей нет, нужен Python 3.10+.

```bash
git clone https://github.com/rappsix/booking-slots.git
cd booking-slots
python -m pytest
```

## Пример

```python
from datetime import date, datetime

from booking_slots import (
    Booking, Service, SlotRules, TimeOff,
    WeeklySchedule, WorkWindow, available_slots,
)

schedule = WeeklySchedule(days={
    "mon": [WorkWindow("10:00", "18:00")],
    "wed": [WorkWindow("10:00", "14:00"), WorkWindow("16:00", "20:00")],
})

haircut = Service("Стрижка", duration_min=60, cleanup_min=15)

slots = available_slots(
    date(2026, 3, 2),
    schedule,
    haircut,
    now=datetime(2026, 3, 1, 12, 0),
    bookings=[Booking(datetime(2026, 3, 2, 12, 0), duration_min=60, cleanup_min=15)],
    time_off=[TimeOff(date(2026, 3, 2), date(2026, 3, 2), "15:00", "16:00")],
    rules=SlotRules(step_min=30, min_lead_min=60),
)
# [10:00, 10:30, 11:00, 13:30, 14:00, 14:30, 16:00, 16:30, 17:00]
```

Сменный график задаётся одной строкой — опорной датой и длиной цикла:

```python
from booking_slots import ShiftSchedule

schedule = ShiftSchedule(
    anchor=date(2026, 3, 2),   # первый день рабочей смены
    work_days=2,
    rest_days=2,
    windows=[WorkWindow("09:00", "21:00")],
)
```

Цикл разворачивается в обе стороны от опорной даты, поэтому график одинаково корректен и для дат до неё: отрицательный остаток по модулю в Python уже даёт нужный сдвиг.

## Синхронизация с Google Calendar

Второй модуль, `booking_slots.gcal`, отвечает за жизнь визита в календаре мастера: обновление OAuth-токена, создание события и разбор занятости из freeBusy — чтобы личные встречи из Google тоже закрывали слоты.

Сети внутри нет: HTTP-вызов передаётся снаружи обычной функцией. Поэтому обновление токена, ретраи и идемпотентность проверяются без моков библиотек и без единого запроса к Google.

```python
from booking_slots import CalendarClient, EventDraft

client = CalendarClient(client_id, client_secret, transport=httpx.request)

result = client.create_event(
    token,
    EventDraft(
        summary="Стрижка — Анна",
        start=datetime(2026, 3, 2, 10, 0),
        end=datetime(2026, 3, 2, 11, 0),
        timezone="Europe/Moscow",
        idempotency_key="visit42",
    ),
    now=datetime.now(),
)
```

Занятость из календаря приводится к тем же интервалам, с которыми работает расчёт слотов:

```python
from booking_slots import gcal_busy_intervals

occupied = gcal_busy_intervals(freebusy_response)
# [(2026-03-02 10:00, 2026-03-02 12:00), (2026-03-02 15:00, 2026-03-02 16:00)]
```

## API

| Функция | Что делает |
|---|---|
| `available_slots(day, schedule, service, ...)` | свободные слоты на конкретный день |
| `visit_slots(day, schedule, services, ...)` | слоты под визит из нескольких услуг подряд |
| `available_dates(schedule, service, ...)` | дни в пределах горизонта, где есть хотя бы один слот |
| `next_slot(schedule, service, ...)` | ближайшее свободное время |
| `CalendarClient.create_event(token, draft, now=...)` | событие в Google Calendar с обновлением токена и ретраями |
| `CalendarClient.ensure_token(token, now)` | обновляет access-токен заранее, до истечения |
| `gcal_busy_intervals(freebusy)` | ответ freeBusy → слитые интервалы занятости |

Все функции принимают `now` явным параметром: внутри ядра нет ни одного обращения к системному времени, поэтому поведение детерминировано и тестируется без подмены часов.

## Решения, которые стоит отметить

**Уборка считается по-разному внутри дня и на его границе.** Буфер после визита блокирует время для следующей записи, но не мешает поставить последний визит вплотную к концу смены — мастер домоет и уйдёт. В коде это две разные величины: `visible` ограничивает окно, `need` проверяет пересечения.

**Удержание слота вместо блокировки.** Когда клиент отменяет визит, окно не выбрасывается в общий доступ мгновенно: оно на время закрепляется за первым в листе ожидания. Владелец удержания видит свой слот свободным, остальные — нет. Истёкшие удержания перестают действовать сами, без фоновой задачи, — достаточно сравнения с `now` в момент запроса.

**Наивное время и часовой пояс мастера.** Все datetime внутри — наивные, в локальной зоне конкретного мастера. Приведение к его зоне делается на границе приложения, до вызова этих функций. Так внутри ядра нет ни одной конвертации и связанного с ней класса ошибок при переходе на летнее время.

**Refresh-token не перезаписывается пустым значением.** Google отдаёт его ровно один раз — при первом согласии, а в ответах на обновление обычно не присылает. Наивное `token = response["refresh_token"]` стирает его при первом же продлении, и мастер идёт проходить OAuth заново. Здесь старое значение сохраняется явно.

**409 от календаря — это успех.** Событие отправляется со своим `id` визита, поэтому повторная отправка не создаёт дубль: Google отвечает конфликтом, и для вызывающего это значит «уже синхронизировано». Ретраи после обрыва связи безопасны.

## Тесты

32 теста на pytest покрывают все ветки: сменные графики в обе стороны от опорной даты, два окна в одном дне, обед внутри окна, отпуск на несколько дней, буфер уборки, минимальный запас времени, удержания активные и истёкшие, визит из нескольких услуг, шаг сетки, а для календаря — обновление токена с запасом, отозванный доступ, повтор при 5xx с экспоненциальной паузой, отказ повторять при 4xx, слияние пересекающихся интервалов занятости.

```bash
python -m pytest -q
# 32 passed
```
